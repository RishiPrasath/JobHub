# Accessibility and Recovery Checklist

Status: checklist prepared; no rendered interface tested

## Accessibility

- [ ] Every core action is keyboard reachable.
- [ ] Focus follows the reading and review order.
- [ ] Focus returns predictably after source or correction dialogs close.
- [ ] Status is conveyed with text and accessible names, not colour alone.
- [ ] Source, claim, state and action are understandable to assistive technology.
- [ ] Content remains usable at increased zoom and narrow widths.
- [ ] Source evidence and correction controls do not require difficult horizontal scrolling.
- [ ] Loading, warning and error states have text equivalents.
- [ ] Labels distinguish `not stated`, `not visible`, `unknown` and `conflicting` in plain language.

## Recovery

- [ ] Original source version is preserved.
- [ ] Confirmed claims survive interruption.
- [ ] Corrections and rejected suggestions survive interruption.
- [ ] Unresolved questions survive interruption.
- [ ] Decision state and rationale survive interruption.
- [ ] A stale source creates a re-review state rather than silent replacement.
- [ ] Undo and restore-original actions are available per claim.
- [ ] Invalid or truncated AI output is not presented as final.
