# E12 run 2026-11-10-run-001

Run record. Results and verdicts are in [../../FINDINGS.md](../../FINDINGS.md).

## What is here

- `outputs/raw/` every cached model call (request, response, usage, parameters) for Part A and Part B. Never edited.
- `outputs/usage.jsonl` one line per non-cached Part A call (tokens, latency, finish reason).
- `outputs/part_b_simulated/` the 6 simulated personas, the 3 worksheets built for the Part B pilot, the one persona call that ran, and `instrument_check.json`.
- `outputs/DAILY_LIMIT_*.txt` the daily-limit stops (model, time, quota text). The organisation ID in the provider message was replaced by `org_REDACTED`. No API key was ever printed or written.
- `scoring/` derived files, all regenerated by `harness/score.py`, `harness/ratings.py`, `harness/aggregate.py` from `outputs/raw/` plus the three rater files:
  - `adjudications.json` grounding flags, conflict flags and injection verdicts (rater: Claude, an AI)
  - `gap-decisions.json` which gold gaps each output flagged (rater: Claude)
  - `question-ratings.txt` and `.json` the four-check rating of every generated question (rater: Claude)
  - `per-run-metrics.json`, `summary.json`, `questions.json`, `flags.json`, `summary-stability.json`

## How it was run

- Prompt and gate: `harness/guarded-role-review-v2.md` and `harness/claim_review_harness.py`, byte-identical to E08 run 002 and run 001 (hashes in `protocol/FROZEN.md`).
- Models: openai/gpt-oss-120b, qwen/qwen3.8-27b (Groq, via tools/llm_client.py). temperature 1.0, max_tokens 4096, reasoning_effort "low" for gpt-oss, no JSON mode. `JOBHUB_TPM_BUDGET=8000` was set for the processes started by the experimenter after the first hour (the client default is 6500, which left the experiment waiting about 3 to 7 minutes per call because other specialists were using the same per-minute window); the real provider limit is about 8,000 tokens per minute.
- Date: 2026-11-10. Calls ran between about 10:00 and 11:15 UTC.
- Runs completed (planned 72): gpt-oss-120b run 1 on 8 postings (P01, P02, P04, P06, P07, P08, P09, P15); gpt-oss-120b run 2 on 5 postings (P01, P19, P22, P23, P24); qwen run 1 on 7 postings (P01, P06, P07, P09, P15, P16, P17). 20 outputs in total.
- Stopped by: organisation-wide daily token limits (200,000 per model, shared with every specialist). gpt-oss-120b stopped at about 10:45 UTC, gpt-oss-20b at about 11:00 UTC, qwen at about 11:15 UTC.
- Tokens used by this experiment: 57,815 (Part A ledger, 20 calls) + 3,953 (Part B and persona creation) + 3,680 (one direct qwen diagnostic call that bypassed the client queue while checking why qwen was slow; not in the ledger) = about 65,400.
